داده‌ساختار چیست؟

داده‌ساختار

داده‌ساختار ({{data structure}}) روشی برای سازمان‌دهی و نمایش داده است، طوری که عملیات مورد نیاز روی آن کارآمد انجام شود. به بیان دقیق‌تر: نمایشی از داده‌ها به‌همراه روابط میان عناصر آن. نمونه‌ها: آرایه، لیست پیوندی، پشته، صف، درخت، جدول درهم‌سازی و گراف.

انتخاب داده‌ساختار مستقیماً تعیین می‌کند که جست‌وجو، درج، حذف و به‌روزرسانی با چه سرعتی انجام شوند. یک داده‌ساختار برای همهٔ کارها بهترین نیست؛ هر کدام بعضی عملیات را ارزان و بعضی را گران می‌کند. هنر طراح این است که بداند کدام عملیات برایش مهم‌تر است.

فروشگاه

فروشگاهی را تصور کنید که همهٔ اجناس را وسط سالن روی هم ریخته است. برای پیدا کردن یک بستهٔ نمک باید تک‌تک اجناس را نگاه کنید. حالا فروشگاهی را تصور کنید که هر جنس را در قفسهٔ مربوط به دسته‌اش گذاشته است: مستقیم به قفسهٔ «ادویه‌ها» می‌روید.

نحوهٔ چیدن اجناس، داده‌ساختار است (روی هم ریختن یا قفسه‌بندی). روش پیدا کردن جنس، الگوریتم است (بررسی تک‌تک اقلام یا جست‌وجو بر اساس دسته). الگوریتم دوم فقط به این دلیل ممکن است که داده‌ساختار مناسبی انتخاب شده است.

الگوریتم و داده‌ساختار با هم کار می‌کنند

الگوریتم

عملیات و گام‌ها؛ مثلاً «یک کلید را جست‌وجو کن».

داده‌ساختار

نمایش داده‌ها؛ مثلاً آرایه یا جدول درهم‌سازی.

مثال: جست‌وجو در یک آرایهٔ مرتب‌نشده \(\Theta(n)\) زمان می‌برد، چون ممکن است مجبور شویم همهٔ خانه‌ها را ببینیم. اما یک جدول درهم‌سازی خوب، جست‌وجو را با امید \(\Theta(1)\) انجام می‌دهد. مسئله یکی است؛ فقط داده‌ساختار عوض شده است. تحلیل الگوریتم (فصل ۱) دقیقاً هزینهٔ زمانی و حافظه‌ای همین انتخاب‌ها را می‌سنجد.

نوع دادهٔ انتزاعی

نوع دادهٔ انتزاعی ({{ADT}})

یک نوع دادهٔ انتزاعی ({{Abstract Data Type}}) مشخص می‌کند که یک ساختار «چه کاری» انجام می‌دهد، نه «چگونه»:

  • چه مقادیری را می‌تواند نگه دارد؛
  • چه عملیاتی در اختیار کاربر قرار می‌دهد؛
  • معنا و قواعد هر عمل چیست؛
  • و جزئیات نمایش داخلی را پنهان می‌کند.
نوع انتزاعی پشته

عملیات پشته ({{Stack}}):

  • \(\text{push}(x)\): \(x\) را روی پشته (بالای آن) بگذار.
  • \(\text{pop}()\): عنصر بالای پشته را بردار و برگردان.
  • \(\text{top}()\): عنصر بالا را بدون برداشتن ببین.
  • \(\text{isEmpty}()\): آیا پشته خالی است؟
S.push(10)
S.push(20)
x = S.pop()          // returns 20

کد کاربر لازم نیست بداند \(S\) با آرایه پیاده شده یا با لیست پیوندی. اگر هر دو پیاده‌سازی از قواعد یکسانی پیروی کنند، می‌توان یکی را با دیگری عوض کرد و کد کاربر بدون تغییر کار خواهد کرد.

فرمان و پدال خودرو

رابط خودرو (فرمان، پدال گاز و ترمز) یک «نوع انتزاعی» است. راننده نمی‌داند موتور بنزینی است یا برقی؛ فقط می‌داند پدال گاز یعنی «سریع‌تر شو». سازنده می‌تواند موتور را عوض کند بدون اینکه راننده رانندگی را از نو یاد بگیرد.

سه سطح: نوع انتزاعی، انتخاب مدل، پیاده‌سازی

  1. نوع انتزاعی: رابط (مثلاً «درج، حذف، جست‌وجو») به‌همراه معنا و تضمین‌های آن.
  2. انتخاب مدل: کدام داده‌ساختار؟ آرایه، لیست، درخت، جدول درهم‌سازی و ... .
  3. پیاده‌سازی: جزئیات واقعی: اندیس‌ها، اشاره‌گرها، چیدمان حافظه و کد.
نوع انتزاعی به‌تنهایی کارایی را مشخص نمی‌کند

«پشته» فقط می‌گوید push و pop چه کار می‌کنند، نه اینکه چقدر طول می‌کشند. زمان اجرا به پیاده‌سازی بستگی دارد. برای همین در این فصل همیشه دو سؤال می‌پرسیم: «چه کاری؟» و «با چه هزینه‌ای؟».

آرایه: حافظهٔ پیوسته و دسترسی مستقیم

آرایه ({{array}}) عناصر را در خانه‌های پشت سر هم حافظه ذخیره می‌کند.

چرا دسترسی به \(arr[i]\) در \(O(1)\) است؟
\[\text{Address}(arr[i]) = \text{base} + i \times \text{element\_size}.\]

نشانی خانه با یک ضرب و یک جمع مستقیم محاسبه می‌شود؛ لازم نیست هیچ خانهٔ دیگری را بخوانیم. این محاسبه برای \(i = 0\) و \(i = 10^9\) به یک اندازه وقت می‌گیرد، پس زمانش به \(n\) بستگی ندارد. این شرط فقط به این دلیل برقرار است که همهٔ عناصر هم‌اندازه و پشت سر هم هستند.

درج در وسط آرایه

فرض کنید آرایه جای خالی دارد و می‌خواهیم ۲۵ را در اندیس ۲ درج کنیم. عناصر اندیس ۲ به بعد باید یک خانه به راست بروند تا جا باز شود.

for j = n-1 downto i          // shift the suffix right, starting from the end
    A[j+1] = A[j]
A[i] = x
n = n + 1
چرا جابه‌جایی را از انتها شروع می‌کنیم؟

اگر از اندیس \(i\) شروع کنیم، \(A[i+1] = A[i]\) مقدار قبلی \(A[i+1]\) را بازنویسی می‌کند و آن را از دست می‌دهیم. با شروع از انتها، هر خانه قبل از اینکه رویش نوشته شود، به خانهٔ بعدی منتقل شده است.

در بدترین حالت (\(i = 0\)) همهٔ \(n\) عنصر جابه‌جا می‌شوند، پس زمان \(\Theta(n)\) است. اگر آرایه پر باشد، باید آرایهٔ بزرگ‌تری گرفت و همه را کپی کرد (همان آرایهٔ پویای فصل ۴).

لیست پیوندی: گره‌هایی که با اشاره‌گر به هم وصل‌اند

مشکل آرایه این بود که عناصر باید کنار هم باشند، پس درج در وسط یعنی جابه‌جا کردن بقیه. ایدهٔ لیست پیوندی ({{linked list}}) این است: عناصر لازم نیست کنار هم باشند؛ کافی است هر عنصر بداند عنصر بعدی کجاست.

گره

هر گره ({{node}}) دو چیز نگه می‌دارد: (۱) یک مقدار ({{data}} یا {{key}}) و (۲) یک اشاره‌گر به گرهٔ بعدی ({{next}}).

پیامد کلیدی

دسترسی با اندیس در زمان ثابت ممکن نیست. برای رسیدن به گرهٔ \(i\)ام باید از ابتدا \(i\) پیوند را دنبال کنیم، چون نشانی آن را هیچ‌جا نداریم.

اشاره‌گر چیست؟

اشاره‌گر ({{pointer}}) متغیری است که نشانی یک گره را نگه می‌دارد؛ مثل کاغذی که آدرس یک خانه رویش نوشته شده، نه خود خانه.

head = null          // empty list: head points to nothing
p = new Node(7)      // create a node; p holds its address
head = p             // now head and p point to the same node
  • \(head\) نشانی اولین گره را نگه می‌دارد.
  • \(p\) و \(head\) می‌توانند به یک گره اشاره کنند.
  • تغییر \(p\) به‌طور خودکار \(head\) را تغییر نمی‌دهد؛ اگر بنویسیم \(p = \text{null}\)، گره و \(head\) دست‌نخورده می‌مانند. فقط کاغذِ \(p\) پاک شده است.
  • یک اشاره‌گر می‌تواند NULL باشد (به هیچ گره‌ای اشاره نکند). پیش از خواندن \(p.data\) یا \(p.next\) باید مطمئن شویم \(p\) به گرهٔ معتبری اشاره می‌کند؛ وگرنه برنامه خطا می‌دهد.
Node:
    data             // the value stored in this node
    next             // address of the next node (null = end of list)

head = null          // the list is represented by one pointer: head

کل لیست با یک اشاره‌گر نمایش داده می‌شود: \(head\). لیست خالی یعنی \(head = \text{null}\).

عملیات روی لیست پیوندی

عمل ۱: پیمایش و چاپ

cur = head
while cur != null
    output cur.data
    cur = cur.next           // advance, or the loop never ends

\(cur\) از \(head\) شروع می‌کند. هر دور حلقه یک گره را ملاقات می‌کند و سپس به گرهٔ بعدی می‌رود. برای لیست \(12 \to 27 \to 19\)، خروجی \(12, 27, 19\) است و پس از گرهٔ ۱۹، \(cur\) برابر null می‌شود و حلقه تمام می‌شود. زمان: \(\Theta(n)\) · حافظهٔ اضافه: \(\Theta(1)\) (فقط یک متغیر \(cur\)).

فراموش کردن جلو بردن اشاره‌گر

اگر خط cur = cur.next را فراموش کنید، \(cur\) همیشه به گرهٔ اول اشاره می‌کند و حلقه هرگز تمام نمی‌شود.

عمل ۲: جست‌وجوی یک کلید

cur = head
while cur != null
    if cur.data = key
        return cur           // return the node's address
    cur = cur.next
return null                  // not found

مثال \(\text{find}(19)\) روی \(12 \to 27 \to 19\): بررسی ۱۲، بررسی ۲۷، بررسی ۱۹ و برگرداندن نشانی آن. بدترین حالت: \(\Theta(n)\)، چون لیست پیوندی دسترسی مستقیم به وسط ندارد (حتی اگر لیست مرتب باشد، جست‌وجوی دودویی ممکن نیست؛ چرا؟ چون رسیدن به «وسط» خودش \(\Theta(n)\) است).

عمل ۳: درج در ابتدای لیست

برای درج گرهٔ جدید \(x\) در ابتدا: گرهٔ جدید را به head قدیمی وصل کن، سپس head را به‌روز کن.

p = new Node(x)
p.next = head
return p                     // p is the new head

زمان: \(\Theta(1)\). این کد برای لیست خالی هم درست است: اگر \(head = \text{null}\)، آنگاه \(p.next\) هم null می‌شود و \(p\) تنها گرهٔ لیست است.

عمل ۴: درج بعد از یک گرهٔ معلوم

if p = null then return
q = new Node(x)
q.next = p.next              // 1) new node points to p's old successor
p.next = q                   // 2) p points to the new node
چرا ترتیب دو خط آخر مهم است؟

اگر اول p.next = q را اجرا کنیم، تنها جایی که نشانی گرهٔ ۴۴ (و بقیهٔ لیست) نگه داشته شده بود، بازنویسی می‌شود. حالا q.next = p.next یعنی q.next = q: گرهٔ جدید به خودش اشاره می‌کند و بقیهٔ لیست برای همیشه گم شده است. قاعده: پیش از بازنویسی یک اشاره‌گر، مطمئن شوید چیزی که به آن اشاره می‌کرد را جای دیگری نگه داشته‌اید.

عمل ۵: حذف گرهٔ بعد از \(p\)

if p = null or p.next = null then return
victim = p.next              // save the node to remove
p.next = victim.next         // link p directly to victim's successor
delete victim                // free its memory (in C++)

اگر \(p\) از قبل معلوم باشد، حذف \(\Theta(1)\) است. اما اگر اول باید \(p\) را پیدا کنیم، پیدا کردنش ممکن است \(\Theta(n)\) طول بکشد.

دام رایج در تحلیل: گره کجاست؟

اشاره‌گر به \(p\) داده شده

درج بعد از \(p\): دو اشاره‌گر عوض می‌شود. زمان \(\Theta(1)\). گرهٔ هدف از قبل معلوم است.

فقط مقدار یا اندیس داده شده

اول باید گرهٔ هدف را با پیمایش پیدا کنیم: ممکن است \(\Theta(n)\) گره بررسی شود، سپس اشاره‌گرها عوض شوند. کل زمان \(\Theta(n)\) در بدترین حالت.

قاعده

هنگام تحلیل زمان یک عمل، همیشه بگویید چه اطلاعاتی به عمل داده شده است. «درج در لیست پیوندی \(O(1)\) است» فقط وقتی درست است که محل درج از قبل معلوم باشد.

لیست دوپیوندی و مقایسه با آرایه

در لیست دوپیوندی ({{doubly linked list}}) هر گره علاوه بر \(next\)، اشاره‌گری به گرهٔ قبلی (\(prev\)) هم دارد.

مزایا

می‌توان به جلو و عقب حرکت کرد؛ و مهم‌تر، می‌توان یک گرهٔ معلوم را بدون جست‌وجوی گرهٔ قبلی‌اش حذف کرد.

هزینه‌ها

یک اشاره‌گر اضافه در هر گره و به‌روزرسانی‌های بیشتر؛ اشتباه در یکی از این به‌روزرسانی‌ها پیوندها را ناسازگار می‌کند.

حذف گرهٔ \(x\) از لیست دوپیوندی
if x.prev != null then x.prev.next = x.next
else head = x.next                  // x was the first node
if x.next != null then x.next.prev = x.prev

در لیست یک‌طرفه برای حذف \(x\) باید گرهٔ قبل از آن را داشته باشیم (چون \(next\) آن باید عوض شود) و پیدا کردنش \(\Theta(n)\) است. در لیست دوپیوندی \(x.prev\) همان گرهٔ قبلی است، پس حذف \(\Theta(1)\) می‌شود.

آرایه یا لیست پیوندی؟

دسترسی به عنصر \(i\)ام\(\Theta(1)\)\(\Theta(n)\)
جست‌وجو در دادهٔ نامرتب\(\Theta(n)\)\(\Theta(n)\)

«محلی بودن حافظه» یعنی چه؟

پردازنده‌ها داده را به‌صورت بلوک‌های پشت سر هم از حافظه به حافظهٔ نهان ({{cache}}) می‌آورند. وقتی خانهٔ \(A[i]\) خوانده می‌شود، چند خانهٔ بعدی هم مجانی می‌آیند. در آرایه این خانه‌ها همان عناصر بعدی‌اند؛ در لیست پیوندی گرهٔ بعدی ممکن است جای دوری از حافظه باشد. برای همین، با وجود مرتبهٔ یکسان، پیمایش آرایه در عمل چند برابر سریع‌تر است.

معکوس کردن لیست پیوندی

می‌خواهیم جهت همهٔ پیوندها را برعکس کنیم، بدون ساختن گرهٔ جدید (درجا).

prev = null
current = head
while current != null
    next = current.next      // save the rest of the list first!
    current.next = prev      // flip this link
    prev = current           // advance prev
    current = next           // advance current
return prev                  // the new head
ناوردا

در شروع هر دور: \(prev\) سرِ بخشِ معکوس‌شده است و \(current\) سرِ بخشِ هنوز دست‌نخورده. هر دور یک گره را از بخش دوم برمی‌دارد و به سر بخش اول می‌چسباند. وقتی بخش دوم تمام شد (\(current = \text{null}\))، \(prev\) سرِ کل لیست معکوس است.

زمان: \(\Theta(n)\) (هر گره دقیقاً یک بار) · حافظهٔ اضافه: \(\Theta(1)\) (سه اشاره‌گر).

چرا \(next\) را اول ذخیره می‌کنیم؟

خط current.next = prev تنها پیوند به بقیهٔ لیست را پاک می‌کند. اگر قبلش آن را در \(next\) نگه نداشته باشیم، بقیهٔ لیست گم می‌شود. این همان درس عمل ۴ است.

پیاده‌سازی لیست پیوندی با آرایه

«اشاره‌گر» لازم نیست حتماً نشانی حافظه باشد؛ می‌تواند اندیس یک آرایه باشد. دو آرایهٔ موازی می‌گیریم: \(Data[\,]\) برای مقدار و \(Next[\,]\) برای اندیس گرهٔ بعدی.

با \(head = 0\)، پیمایش منطقی این است: \(0{:}\,10 \to 2{:}\,20 \to 1{:}\,30\) (چون \(Next[0] = 2\) و \(Next[2] = 1\) و \(Next[1] = \text{null}\)). یعنی لیست \(10, 20, 30\) است، با اینکه در آرایه ترتیب فیزیکی \(10, 30, 20\) است.

درج ۱۵ بین ۱۰ و ۲۰ با خانهٔ آزاد ۳
Data[3] = 15
Next[3] = 2       // 15 -> 20
Next[0] = 3       // 10 -> 15

ترتیب منطقی جدید: \(10 \to 15 \to 20 \to 30\). هیچ عنصری جابه‌جا نشد؛ فقط دو «اشاره‌گر» عوض شد.

حذف ۲۰: گرهٔ قبلی‌اش اکنون اندیس ۳ (یعنی ۱۵) است، پس \(Next[3] = 1\). حالا خانهٔ ۲ آزاد است و ترتیب منطقی \(10 \to 15 \to 30\) می‌شود.

ایدهٔ کلیدی

ترتیب منطقی را آرایهٔ \(Next\) تعیین می‌کند، نه جای فیزیکی عناصر در آرایه.

مدیریت خانه‌های آزاد

خانه‌های آزاد را هم می‌توان با همان آرایهٔ \(Next\) در یک «لیست آزاد» ({{free list}}) به هم زنجیر کرد. برای گرفتن خانهٔ جدید، اولین عضو لیست آزاد را برمی‌داریم و پس از حذف، خانه را به سر لیست آزاد برمی‌گردانیم. هر دو \(O(1)\) هستند. این کار همان کاری است که \(\texttt{new}\) و \(\texttt{delete}\) پشت صحنه انجام می‌دهند.

لیست دوری: شمارش گره‌ها با الگوریتم فلوید

گاهی (عمداً یا به‌خاطر یک باگ) پیوند آخرین گره به جای null، به یکی از گره‌های قبلی برمی‌گردد. ساختار حاصل یک پیشوند غیردوری دارد و بعد وارد یک دور می‌شود. مسئله: تعداد گره‌های متمایز را بشمارید.

چرا پیمایش معمولی کار نمی‌کند؟

در ساختار دوری هیچ پیوند null وجود ندارد، پس حلقهٔ while cur != null هرگز تمام نمی‌شود. می‌توان نشانی همهٔ گره‌های دیده‌شده را در یک مجموعه نگه داشت، ولی این \(O(n)\) حافظهٔ اضافه می‌خواهد. الگوریتم فلوید با \(O(1)\) حافظه کار می‌کند.

فلوید (لاک‌پشت و خرگوش) + دو شمارش
  1. با دو اشاره‌گر \(slow\) (یک قدم در هر گام) و \(fast\) (دو قدم در هر گام) از \(head\) راه بیفت تا به هم برسند (نقطهٔ ملاقات).
  2. یک اشاره‌گر را به \(head\) برگردان و دیگری را در نقطهٔ ملاقات نگه دار؛ هر دو را یک قدم یک قدم جلو ببر. جایی که به هم می‌رسند، ورودی دور است.
  3. گره‌های قبل از ورودی را بشمار (طول پیشوند).
  4. از ورودی یک دور کامل بزن و گره‌های دور را بشمار.
  5. جواب: طول پیشوند + طول دور.
slow = head, fast = head                 // step 1: find a meeting point
repeat
    slow = slow.next
    fast = fast.next.next
until slow = fast
p1 = head, p2 = slow                     // step 2: find the cycle entry
while p1 != p2
    p1 = p1.next, p2 = p2.next
entry = p1
prefix = 0, p = head                     // step 3: count the prefix
while p != entry
    prefix = prefix + 1, p = p.next
cycle = 1, p = entry.next                // step 4: count the cycle
while p != entry
    cycle = cycle + 1, p = p.next
return prefix + cycle                    // step 5
چرا الگوریتم فلوید درست است؟

فرض کنید طول پیشوند \(\mu\) و طول دور \(\lambda\) باشد (در مثال، \(\mu = 2\) و \(\lambda = 3\)).

(الف) حتماً به هم می‌رسند: پس از \(\mu\) گام، \(slow\) وارد دور می‌شود و \(fast\) هم جایی درون دور است. از آن پس در هر گام، \(fast\) یک قدم بیشتر از \(slow\) جلو می‌رود؛ پس فاصلهٔ \(fast\) تا رسیدن به \(slow\) (در جهت حرکت) هر گام یکی کم می‌شود و حداکثر پس از \(\lambda\) گام صفر می‌شود.

(ب) زمان ملاقات مضرب \(\lambda\) است: اگر ملاقات در گام \(t\) رخ دهد، \(slow\) مسافت \(t\) و \(fast\) مسافت \(2t\) را پیموده و هر دو در یک گره‌اند. پس \(fast\) دقیقاً چند دور کامل بیشتر زده است: \(2t - t = t\) مضربی از \(\lambda\) است.

(ج) گام ۲ به ورودی دور می‌رسد: \(p_1\) از \(head\) و \(p_2\) از نقطهٔ ملاقات (یعنی \(t\) قدم پس از \(head\)) هم‌زمان یک‌قدمی جلو می‌روند. پس از \(\mu\) قدم، \(p_1\) در ورودی دور است و \(p_2\) در نقطه‌ای \(t + \mu\) قدم پس از \(head\). چون \(t\) مضرب \(\lambda\) است و جای گره‌های درون دور هر \(\lambda\) قدم تکرار می‌شود، \(t + \mu\) قدم همان جایی است که \(\mu\) قدم: ورودی دور. قبل از آن هم نمی‌توانند به هم برسند، چون \(p_1\) هنوز روی پیشوند است و \(p_2\) درون دور.

اجرا روی مثال شکل

گره‌ها را به ترتیب پیمایش شماره کنید: \(A{=}0, B{=}1, C{=}2, D{=}3, E{=}4\) و پس از آن دوباره \(C\).

  • گام ۱: \(slow = B\)، \(fast = C\). گام ۲: \(slow = C\)، \(fast = E\). گام ۳: \(slow = D\)، \(fast = D\) ← ملاقات در \(D\) با \(t = 3\) (مضرب \(\lambda = 3\) ✓).
  • \(p_1 = A, p_2 = D\) ← \(p_1 = B, p_2 = E\) ← \(p_1 = C, p_2 = C\): ورودی دور \(C\) پس از \(\mu = 2\) قدم.
  • پیشوند: \(A, B\) یعنی ۲. دور: \(C \to D \to E \to C\) یعنی ۳. جواب: \(5\).

زمان: \(O(n)\) · حافظهٔ اضافه: \(O(1)\). اگر لیست کاملاً حلقوی باشد (دم به سر برگردد)، کافی است از \(head\) یک دور کامل بزنیم و بشماریم.

لیست حلقوی و مسئلهٔ ژوزفوس

مسئلهٔ ژوزفوس

\(n\) نفر در یک دایره ایستاده‌اند. از نفر ۱ شروع می‌کنیم و ۱، ۲، ...، \(k\) می‌شماریم؛ نفرِ \(k\)ام حذف می‌شود و شمارش از نفر بعدی از نو شروع می‌شود. آخرین نفر باقی‌مانده کیست؟

لیست حلقوی ({{circular linked list}}) که در آن دم به سر وصل است، دقیقاً مدل همین دایره است: «نفر بعدی» همیشه \(next\) است، حتی برای آخرین نفر. 

build a circular list 1..n
current = node 1
previous = node n
while more than one node remains
    repeat k-1 times                    // walk k-1 steps
        previous = current
        current = current.next
    previous.next = current.next         // remove current
    delete current
    current = previous.next              // counting restarts here
return current.value
چند گام اول

شروع: \(current = 1\). دو قدم: \(current = 3\) ← حذف ۳؛ \(current = 4\). دو قدم: \(current = 6\) ← حذف ۶؛ \(current = 7\). دو قدم (۷ ← ۱ ← ۲): حذف ۲؛ \(current = 4\). به همین ترتیب ۷، ۵ و ۱ حذف می‌شوند و ۴ می‌ماند.

زمان: \(n - 1\) حذف و برای هر کدام \(k - 1\) قدم: \(O(nk)\). برای \(k\) ثابت، \(O(n)\). حافظه: \(O(n)\).

فرمول بازگشتی

اگر افراد را از ۰ شماره کنیم و \(J(n)\) شمارهٔ بازمانده باشد: \(J(1) = 0\) و \(J(n) = (J(n-1) + k) \bmod n\). (پس از اولین حذف، مسئله همان مسئلهٔ \(n-1\) نفره است که شماره‌هایش \(k\) واحد جابه‌جا شده.) برای \(n = 7, k = 3\): \(0, 1, 1, 0, 3, 0, 3\)؛ یعنی شمارهٔ ۳ از صفر، که همان نفر ۴ است. این روش بدون شبیه‌سازی \(O(n)\) زمان می‌برد.

پشته: آخرین ورودی، اولین خروجی

پشته ({{LIFO}}: {{Last In, First Out}})

عملیات: \(\text{push}(x)\) (افزودن \(x\) به بالا)، \(\text{pop}()\) (برداشتن عنصر بالا)، \(\text{top}()\) (دیدن عنصر بالا)، \(\text{isEmpty}()\) (آیا خالی است؟). فقط عنصر بالا مستقیماً در دسترس است.

دو پیاده‌سازی \(O(1)\)
PUSH(x):  if top = capacity-1 then overflow
          top = top + 1;  A[top] = x
POP():    if top = -1 then underflow
          x = A[top];  top = top - 1;  return x

با لیست پیوندی: push همان «درج در ابتدا» و pop همان «حذف از ابتدا» است. هر دو \(O(1)\). (چرا در ابتدا و نه انتها؟ چون حذف از انتهای لیست یک‌طرفه گرهٔ قبلی را لازم دارد.)

پشته کجا ظاهر می‌شود؟

کاربردچرا پشته؟
فراخوانی توابعتابعی که تابع دیگری را صدا می‌زند معلق می‌شود. «پشتهٔ فراخوانی» محل بازگشت و متغیرهای محلی هر تابع را نگه می‌دارد.
برگرداندن ({{undo}}) و عقب‌گردآخرین کار، اولین کاری است که برگردانده می‌شود. جست‌وجوی عمق‌اول (DFS) هم صریح یا ضمنی (با بازگشت) از پشته استفاده می‌کند.
پشتهٔ یکنواپشته‌ای از مقادیر یا اندیس‌ها به ترتیب مرتب، برای مسائل «بزرگ‌تر/کوچک‌تر بعدی» (بخش بعد).
قدرت واقعی پشته

قدرت پشته فقط در عملیاتش نیست؛ در این است که ساختار «تازه‌ترین کارِ هنوز حل‌نشده» را دقیقاً مدل می‌کند. هر جا کارهایی تودرتو دارید (پرانتزها، فراخوانی‌ها، زیرمسئله‌ها) که آخرین شروع‌شده باید اول تمام شود، به پشته فکر کنید.

بازگشت از پشته استفاده می‌کند، حتی اگر آن را نبینید

if n <= 1 then return 1
return n * FACTORIAL(n-1)

\(\text{factorial}(3)\) تابع \(\text{factorial}(2)\) را صدا می‌زند و آن هم \(\text{factorial}(1)\) را، تا به حالت پایه برسیم. هر فراخوانی باید به خاطر بسپارد کجا ادامه دهد و کدام \(n\) مال اوست. این اطلاعات در یک «قاب» ({{frame}}) روی پشتهٔ زمان اجرا گذاشته می‌شود.

سرریز پشته

حافظهٔ پشتهٔ فراخوانی محدود است. بازگشتی که خیلی عمیق شود (مثلاً \(\text{factorial}(10^6)\) یا بازگشت بی‌پایان به‌خاطر حالت پایهٔ غلط) پشته را پر می‌کند و برنامه با خطای {{stack overflow}} متوقف می‌شود.

کاربرد پشته: نزدیک‌ترین قیمت بزرگ‌تر بعدی

مسئله

قیمت‌های روزانهٔ یک سهم \(P[0..n-1]\) داده شده است. برای هر روز \(i\)، قیمتِ اولین روز بعدی \(j > i\) را پیدا کنید که \(P[j] > P[i]\). اگر چنین روزی نبود، جواب \(-1\) (یا —).

«اولین» نه «بیشترین»

«اولین روز بعدی» یعنی نزدیک‌ترین اندیس سمت راست با قیمت اکیداً بیشتر، نه بیشترین قیمت آینده. مثلاً برای روز ۲ (قیمت ۶۰) جواب ۷۰ است، نه ۸۵.

الگوریتم ساده: \(\Theta(n^2)\)

for i = 0 to n-1
    next[i] = -1
    for j = i+1 to n-1
        if P[j] > P[i] then
            next[i] = P[j]
            break

برای هر \(i\) ممکن است تقریباً همهٔ اندیس‌های بعدی را بررسی کنیم. در بدترین حالت (قیمت‌های نزولی، که هیچ‌کدام جواب ندارند) تعداد مقایسه‌ها \((n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2} = \Theta(n^2)\) است. این الگوریتم ساده و درست است، اما اسکن‌های تکراری کاری را دوباره انجام می‌دهند که پشته می‌تواند از آن پرهیز کند.

ایدهٔ پشته

  • روزهایی را که هنوز جوابشان معلوم نیست («حل‌نشده») روی یک پشته نگه دار.
  • وقتی قیمت جدیدی می‌رسد، همهٔ قیمت‌های کوچک‌ترِ بالای پشته را حل می‌کند: آن‌ها را pop کن و جوابشان را قیمت جدید بگذار.
  • سپس اندیس روز جاری را push کن (جواب خودش هنوز معلوم نیست).
قیمت جاری ۷۵

اگر بالای پشته روز ۴ با قیمت ۶۰ باشد، ۷۵ اولین قیمت بعدی بزرگ‌تر از ۶۰ است: روز ۴ را pop کن و جوابش را ۷۵ بگذار. ادامه بده: روز ۳ (۷۰) هم کوچک‌تر است، pop و جواب ۷۵. وقتی بالای پشته \(\ge 75\) شد (روز ۱ با ۸۰) یا پشته خالی شد، متوقف شو.

n = length(P)
ans = array of n values, all -1
create empty stack st                    // stores indices
for i = 0 to n-1
    while st is not empty and P[st.top] < P[i]
        ans[st.pop()] = P[i]             // P[i] resolves this day
    st.push(i)
return ans
iP[i]popped (answer = P[i])stack after (indices: prices)
0100—[0:100]
180—[0:100, 1:80]
260—[0:100, 1:80, 2:60]

460—[0:100, 1:80, 3:70, 4:60]
5754, 3[0:100, 1:80, 5:75]

در پایان روزهای ۰ و ۶ روی پشته مانده‌اند، پس جوابشان \(-1\) می‌ماند. جواب نهایی: \(-1, 85, 70, 75, 75, 85, -1\) ✓.

جزئیات مهم
  • اندیس ذخیره کن، نه فقط قیمت: باید بدانیم جواب را در کدام خانهٔ \(ans\) بنویسیم.
  • از \(<\) برای «اکیداً بزرگ‌تر» استفاده کن؛ \(\le\) فقط اگر مسئله «بزرگ‌تر یا مساوی» بخواهد.
  • اندیس‌هایی که حل نشده می‌مانند، \(-1\) باقی می‌مانند.
  • ناوردا: قیمت‌های روی پشته از پایین به بالا نزولی‌اند (به همین دلیل «پشتهٔ یکنوا»). چرا؟ هر عنصری که push می‌شود، قبلش همهٔ عناصر کوچک‌تر از خودش را از بالای پشته برداشته است.
چرا \(\Theta(n)\)؟ (شمارش سرشکنی)

حلقهٔ while ممکن است در یک دور خیلی اجرا شود (مثلاً روز ۶ دو pop داشت)، پس ضرب «\(n\) دور × بدترین while» کران \(O(n^2)\) می‌دهد. اما مثل پشتهٔ multipop در فصل ۴ (روش انبوهه)، از دید هر اندیس حساب کنید: هر اندیس دقیقاً یک بار push و حداکثر یک بار pop می‌شود. پس در کل اجرا حداکثر \(n\) push و \(n\) pop داریم و بقیهٔ بررسی‌ها هم \(O(n)\) هستند:

\[\text{کل کار} = O(n) + O(n) = O(n).\]

از طرف دیگر هر الگوریتمی باید همهٔ قیمت‌ها را دست‌کم یک بار بخواند، پس \(\Omega(n)\) هم هست. در نتیجه \(\Theta(n)\).

کاربرد پشته: قطار و جایگشت‌ها

مسئلهٔ خط فرعی

واگن‌ها به ترتیب \(1, 2, \dots, n\) وارد می‌شوند. یک خط فرعی ({{siding}}) مثل پشته رفتار می‌کند: واگنی که آخر وارد شده، اول خارج می‌شود. آیا می‌توان ترتیب خروجی دلخواه \(\pi\) را تولید کرد؟

هدف \(2, 1, 4, 3\): ممکن

push ۱، push ۲؛ pop ۲، pop ۱. push ۳، push ۴؛ pop ۴، pop ۳. ✓

هدف \(3, 1, 2\): ناممکن

برای خروج ۳ باید ۱، ۲، ۳ را push کنیم و ۳ را pop کنیم. حالا ۲ روی ۱ است، پس ۱ نمی‌تواند خروجی بعدی باشد. ✗

نکتهٔ کلیدی: محدودیت ترتیب پشته؛ واگنی که آخر وارد شده باید پیش از همهٔ واگن‌های زیرش خارج شود.

شرط لازم و کافی: شبیه‌سازی حریصانه

next_in = 1                  // next car waiting at the input
create empty stack S
for t = 1 to n               // we want to output π[t]
    while (S is empty or S.top != π[t]) and next_in <= n
        S.push(next_in)
        next_in = next_in + 1
    if S.top = π[t] then S.pop()
    else return false        // input exhausted, top cannot match
return true
چرا این شبیه‌سازی هم لازم است و هم کافی؟

فرض کنید خروجی بعدیِ مورد نیاز \(x = \pi[t]\) باشد. فقط سه حالت ممکن است و در هر کدام تنها یک کار مجاز است:

  • \(x\) بالای پشته است: باید همین حالا pop شود. هر push دیگری آن را زیر واگن دیگری دفن می‌کند که باید پیش از آن خارج شود، ولی خروجی بعدی باید \(x\) باشد.
  • \(x\) هنوز وارد نشده: تنها راه رساندن \(x\) به بالای پشته، push کردن واگن‌های ورودی تا رسیدن به \(x\) است.
  • \(x\) در پشته است ولی بالا نیست: واگن‌های بالای آن باید زودتر خارج شوند، ولی خروجی بعدی باید \(x\) باشد: ناممکن.

چون در هر گام انتخاب اجباری است، اگر شبیه‌سازی گیر کند هیچ راه دیگری هم وجود ندارد، و اگر تا آخر برود، خودش یک دنبالهٔ معتبر push/pop ساخته است. هر واگن یک بار push و یک بار pop می‌شود، پس زمان \(\Theta(n)\) است.

چند جایگشت ممکن است؟

یک جایگشت دقیقاً وقتی تولیدشدنی است که الگوی «۳۱۲» نداشته باشد: سه موقعیت \(i < j < k\) با \(\pi_j < \pi_k < \pi_i\) (یعنی بزرگی، بعد کوچکی، بعد متوسطی). تعداد جایگشت‌های تولیدشدنی عدد کاتالان \(C_n = \frac{1}{n+1}\binom{2n}{n}\) است. برای \(n = 3\): از ۶ جایگشت، ۵ تا ممکن‌اند و فقط \(3, 1, 2\) ناممکن است.

صف: اولین ورودی، اولین خروجی

صف ({{FIFO}}: {{First In, First Out}})

صف نوعی لیست است که فقط اجازهٔ افزودن به انتها و حذف از ابتدا را می‌دهد. عملیات:

  • \(\text{enqueue}(x)\): درج \(x\) در انتهای صف (عقب).
  • \(\text{dequeue}()\): حذف و برگرداندن عنصر ابتدای صف (جلو).
  • \(\text{front}()\): برگرداندن عنصر ابتدای صف بدون حذف.
  • \(\text{isEmpty}()\): آیا صف خالی است؟ و \(\text{size}()\): تعداد عناصر.

صف با آرایه: چرا جلو و عقب مهم‌اند؟

روش ساده: جابه‌جا کردن

صف همیشه از خانهٔ ۰ شروع شود. پس از حذف اولین عنصر، همهٔ عناصر باقی‌مانده یک خانه به چپ می‌روند. هر dequeue \(\Theta(n)\) می‌شود و هدف یک صف کارا از بین می‌رود.

روش آرایهٔ حلقوی

به‌جای جابه‌جا کردن عناصر، اندیس‌های جلو و عقب را جابه‌جا کن. هر دو عمل \(\Theta(1)\) می‌شوند.

صف حلقوی: اندیس‌ها دور می‌زنند

اگر فقط اندیس‌ها را جلو ببریم، دیر یا زود به انتهای آرایه می‌رسیم، در حالی که خانه‌های ابتدایی (که عناصرشان dequeue شده‌اند) خالی‌اند. راه حل: آرایه را حلقوی فرض کنیم؛ بعد از آخرین خانه، دوباره خانهٔ ۰ می‌آید:

\[\text{next}(i) = (i + 1) \bmod C.\] 
isEmpty:  return count = 0
isFull:   return count = C

enqueue(x):
    if isFull then report overflow
    A[rear] = x
    rear = (rear + 1) mod C
    count = count + 1

dequeue():
    if isEmpty then report underflow
    x = A[front]
    front = (front + 1) mod C
    count = count - 1
    return x
\(front\)اندیس عنصر بعدی برای حذف. \(rear\)اندیسی که عنصر بعدی در آن درج می‌شود. \(count\)تعداد عناصر ذخیره‌شده. خالی اگر و فقط اگر \(count = 0\)؛ پر اگر و فقط اگر \(count = C\).

پر و خالی را چطور از هم تشخیص دهیم؟

مشکل

اگر فقط \(front\) و \(rear\) را داشته باشیم، در صف خالی داریم \(front = rear\). اما اگر \(C\) عنصر درج کنیم، \(rear\) دقیقاً یک دور می‌زند و دوباره \(front = rear\) می‌شود: صف پر هم همین وضعیت را دارد! پس به اطلاعات بیشتری نیاز داریم.

روش الف: نگه داشتن count

\(count = 0\) یعنی خالی و \(count = C\) یعنی پر. ساده است و صف می‌تواند از همهٔ \(C\) خانه استفاده کند.

روش ب: یک خانه را خالی بگذار

خالی: \(front = rear\). پر: \((rear + 1) \bmod C = front\). ظرفیت قابل استفاده \(C - 1\) است؛ آن یک خانهٔ خالی ابهام پر/خالی را از بین می‌برد.

دو قرارداد را با هم قاطی نکنید

ناوردایی که انتخاب می‌کنید، آزمون‌های درست را تعیین می‌کند. پیاده‌سازی‌ای که count نگه می‌دارد ولی پر بودن را با \((rear+1) \bmod C = front\) می‌آزماید، یک خانه را بی‌دلیل هدر می‌دهد یا بدتر، خطا دارد.

خودآزمایی فصل ۵

  1. در پیاده‌سازی آرایه‌ای بخش «پیاده‌سازی لیست با آرایه»، پس از درج ۱۵ و حذف ۲۰، پیمایش از head چه خروجی‌ای می‌دهد؟ مقادیر \(Next\) را بنویسید.
    \(Next[0] = 3\)، \(Next[3] = 1\)، \(Next[1] = \text{null}\) (خانهٔ ۲ آزاد است). خروجی: \(10, 15, 30\).
  2. آیا ترتیب خروجی \(4, 3, 5, 1, 2\) با خط فرعی ممکن است؟
    push ۱..۴، pop ۴؛ ۳ بالاست، pop ۳؛ push ۵، pop ۵؛ حالا بالای پشته ۲ است ولی ۱ لازم است و ورودی تمام شده: ناممکن (الگوی ۳۱۲: ۴، ۱، ۲).
  3. جواب «بزرگ‌تر بعدی» را برای \(2, 7, 3, 5, 4, 6, 8\) بنویسید.
    \(7, 8, 5, 6, 6, 8, -1\).
  4. صف حلقوی با \(C = 4\) و روش «یک خانه خالی» حداکثر چند عنصر نگه می‌دارد؟
    \(C - 1 = 3\) عنصر.
  5. صفی با دو پشته بسازید. هزینهٔ سرشکن هر عمل چقدر است؟
    enqueue: push در پشتهٔ ورودی. dequeue: اگر پشتهٔ خروجی خالی بود، همهٔ عناصر پشتهٔ ورودی را pop و در پشتهٔ خروجی push کن (ترتیبشان برعکس می‌شود)، سپس از پشتهٔ خروجی pop کن. هر عنصر حداکثر دو بار push و دو بار pop می‌شود، پس هزینهٔ سرشکن \(O(1)\) است (روش انبوههٔ فصل ۴)، هرچند یک dequeue تکی ممکن است \(\Theta(n)\) باشد.
  6. چرا در الگوریتم فلوید لازم است \(fast\) دقیقاً دو قدم برود؟ اگر سه قدم برود چه؟
    با سرعت ۲، فاصلهٔ \(fast\) تا \(slow\) در هر گام دقیقاً یکی کم می‌شود، پس هرگز از روی \(slow\) نمی‌پرد و حتماً به آن می‌رسد. با سرعت ۳ فاصله هر گام دو واحد (به پیمانهٔ \(\lambda\)) کم می‌شود؛ اگر طول دور زوج و فاصلهٔ اولیه فرد باشد، فاصله همیشه فرد می‌ماند و هرگز به هم نمی‌رسند. مثلاً \(\lambda = 2\) و فاصلهٔ ۱.
